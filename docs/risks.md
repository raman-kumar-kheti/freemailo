# Security and operational risks

Reviewed 2026-11-21 against the running local application. This is an engineering review, not a penetration test or a claim of regulatory compliance. Passing development checks does not establish public production readiness.

| Risk | Implemented control and evidence | Residual work / limit |
| --- | --- | --- |
| Open relay and sender spoofing | Port 25 does not advertise AUTH; unauthenticated external RCPT denied; submission requires TLS, SASL and envelope sender ownership; internal Sieve relay requires a pinned certificate. Real SMTP regression tests cover these paths. | Recheck from an independent external network after each host/proxy/firewall change. Header From impersonation and compromised authenticated accounts need outbound abuse policy. |
| Forged authentication badges | Rspamd replaces supplied results on inbound and authenticated/local paths. API accepts only the configured local issuer and ignores comments/quoted claims. | Imported/historical messages are not retroactively authenticated. A pass result is not a safe-sender guarantee. |
| Email HTML and attachments | DOMPurify, sandboxed iframe, remote-image consent, bounded uploads, safe attachment response filenames, and browser regression checks. | Antivirus is not deployed. Uploaded attachments are buffered before aggregate-size validation; enforce proxy body limits, memory limits and concurrent-send limits for public traffic. |
| Session theft and CSRF | HttpOnly Strict cookies, production Secure flag, short access expiry, transactional refresh rotation, origin/header validation, inactive-account checks. | A stolen access token remains useful until expiry unless the account is disabled. Password changes revoke refresh tokens; global token-family reuse revocation is not implemented. |
| Credential attacks | Login throttle is 20/minute per API process; general burst/sustained limits apply. Mailbox credentials are verified by Dovecot. | Host-level IMAP/SMTP ban rules, external alerts, MFA and distributed rate limiting are not provided. Trust only explicit proxy addresses. |
| Privileged service compromise | API/web non-root, no Docker socket, validated provisioning paths, DKIM response redaction. | API has master-mail credentials and access to all Maildir/DKIM data by design. Isolate the host, restrict admin access, rotate secrets and audit access. |
| Dependency and image vulnerabilities | Locked npm dependencies, local audits, reproducible application builds and CI checks. | Zero npm findings only reflects that audit's database and time. OS image scanning, digest pinning, patch cadence and an independent security review remain deployment responsibilities. |
| Job or data loss | SQL-backed jobs, reconciliation, retries/DLQ, Redis noeviction/AOF, persistent queue, deletion archives, checksummed backups and isolated restore test. | Monitor capacity and stalled jobs. Encrypt/off-site backups and test full service recovery on a separate host. Archives contain mail, passwords and keys. No high-availability/failover design is implemented. |
| Certificate expiry | Renewal hook updates mail certs, the internal relay pin, and reloads daemons; production API requires verification. | Real public issuance/renewal and web HTTPS must be exercised on the deployment host. Restarting Dovecot requires a Postfix reload to discard cached SASL connections. |
| Deliverability and DNS | Domain validation, exact DNS diagnostics, DKIM generation/signing, SPF/DMARC support and spam rejection tests. | Public MX/PTR, DNS propagation, IP reputation, outbound port restrictions and independent-provider delivery are unverified locally. |
| Resource exhaustion | Pagination, bounded realtime connections, network timeouts, limited thread results and bounded quota-file reads. | Load evidence covers one 10,000-message development mailbox, not concurrent tenants. Establish connection, memory, disk and throughput budgets under representative production load. |
| Privacy and retention | Secrets are redacted from API responses; deletion archives preserve recoverability. | Mail logs include addresses/message metadata. Define retention, deletion, backup encryption, access policies and jurisdictional requirements before hosting others' mail. |

See [application-review.md](application-review.md) for the tested scope and [deployment-runbook.md](deployment-runbook.md) for release gates. Do not use `.env.dev`, publicly expose the controller/database, or describe all residual risks as low simply because local tests pass.
